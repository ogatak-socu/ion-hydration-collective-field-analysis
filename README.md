# Ion Hydration Collective Field Analysis

C programs for analyzing ion-induced structural and collective organization of hydration water from molecular dynamics (MD) trajectories.

This repository contains the analysis programs used for the calculations corresponding to **Figures 1–3** of the associated manuscript:

> **Ion Hydration Generates an Extended Collective Hydration Field in Water**

The programs are designed to process multiple independent MD trajectories separately and then merge the trajectory-level results for the final analysis.

---

## Overview

The analysis is divided into two pipelines:

1. **Vector analysis**
   - `cal_vector`
   - `accumulate_vector`

2. **Charge analysis**
   - `cal_charge`
   - `accumulate_charge`

In the associated study, **25 independent trajectories** were analyzed for each system. Each trajectory was processed independently, and the resulting trajectory-level outputs were subsequently merged.

The programs are written in **C** and are compiled using the supplied `makefile`.

## Programs

### `cal_vector`

`cal_vector` calculates vector quantities for **one independent trajectory set**.

The calculated quantities include:

- dipole vectors;
- force vectors;
- backward displacement vectors;
- forward displacement vectors.

Each independent trajectory is analyzed separately.

For example:

```text
trajectory 1  -> cal_vector -> vector output 1
trajectory 2  -> cal_vector -> vector output 2
trajectory 3  -> cal_vector -> vector output 3
      ...
trajectory N  -> cal_vector -> vector output N
```

The resulting trajectory-level vector outputs are subsequently merged using `accumulate_vector`.

### `accumulate_vector`

`accumulate_vector` combines the trajectory-level outputs generated by `cal_vector`.

```text
vector output 1  \
vector output 2   \
vector output 3    >  accumulate_vector  -> merged vector data
      ...         /
vector output N  /
```

The merged data are used for the collective vector analyses.

### `cal_charge`

`cal_charge` calculates the spatially resolved solvent charge distribution for **one independent trajectory set**.

Each trajectory is processed separately, in the same manner as for `cal_vector`.

```text
trajectory 1  -> cal_charge -> charge output 1
trajectory 2  -> cal_charge -> charge output 2
trajectory 3  -> cal_charge -> charge output 3
      ...
trajectory N  -> cal_charge -> charge output N
```

### `accumulate_charge`

`accumulate_charge` combines the trajectory-level charge outputs generated by `cal_charge`.

```text
charge output 1  \
charge output 2   \
charge output 3    >  accumulate_charge  -> merged charge data
      ...         /
charge output N  /
```

## Build

Move to the `analy_ion` directory and compile the programs using the supplied `makefile`:

```bash
cd analy_ion
make
```

The build generates the following executable programs:

```text
cal_vector
accumulate_vector
cal_charge
accumulate_charge
```

## Running the Sample Calculations

The sample input files use **relative paths** for the topology, coordinates, trajectories, grid data, and output directory.

Therefore, the sample calculations should be executed from the `analy_ion/sample` directory.

After compilation:

```bash
cd sample
```

All programs use the following command format:

```bash
../program_name -op input_file
```

For example:

```bash
../cal_vector -op nacl_sample.1.in
```

### Vector analysis

Run `cal_vector` independently for each trajectory set:

```bash
../cal_vector -op nacl_sample.1.in
../cal_vector -op nacl_sample.2.in
../cal_vector -op nacl_sample.3.in
```

After all trajectory-level calculations have finished, merge the outputs:

```bash
../accumulate_vector -op nacl_sample.acc.in
```

### Charge analysis

Run `cal_charge` independently for each trajectory set:

```bash
../cal_charge -op nacl_sample.1.in
../cal_charge -op nacl_sample.2.in
../cal_charge -op nacl_sample.3.in
```

After all trajectory-level calculations have finished, merge the outputs:

```bash
../accumulate_charge -op nacl_sample.acc.in
```

The calculated files are written to the `output` directory according to the output prefixes specified in the input files.

## Sample Input Files

The `sample` directory contains two types of input files.

### Trajectory-level input files

```text
nacl_sample.1.in
nacl_sample.2.in
nacl_sample.3.in
```

These files are used by:

```text
cal_vector
cal_charge
```

Each file corresponds to one independent trajectory set.

### Accumulation input file

```text
nacl_sample.acc.in
```

This file is used by:

```text
accumulate_vector
accumulate_charge
```

The parameter `number_of_vectors` specifies how many independently calculated trajectory-level output sets are to be merged.

For the supplied sample:

```text
number_of_vectors  3
```

corresponds to the three trajectory-level calculations generated from:

```text
nacl_sample.1.in
nacl_sample.2.in
nacl_sample.3.in
```

In the associated study, 25 independent trajectories were analyzed.

## Trajectory-Level Input Parameters

A trajectory-level input file contains entries such as:

```text
prmtop                  leap/nacl.prmtop
inpcrd                  leap/nacl.inpcrd

system_size             input/system.size
spherical_grid_points_file      input/spherical_points.200.out

target_atom_index       1

rn                      15
delta_d                 0.2

rc                      2.5
alpha                   5.0

dip_vector_prefix       output/dip_vector
frc_vector_prefix       output/frc_vector
bck_vector_prefix       output/bck_vector
fwd_vector_prefix       output/fwd_vector

charge_prefix           output/charge

file_no                 1

mdcrd                   md.1/nacl.md3.mdcrd.gz
mdcrd                   md.1/nacl.md4.mdcrd.gz
mdcrd                   md.1/nacl.md5.mdcrd.gz

mdfrc                   md.1/nacl.md3.mdfrc.gz
mdfrc                   md.1/nacl.md4.mdfrc.gz
mdfrc                   md.1/nacl.md5.mdfrc.gz
```

### Parameter descriptions

| Keyword | Description |
|---|---|
| `prmtop` | Amber topology (`prmtop`) file for the molecular system. |
| `inpcrd` | Amber restart/coordinate file defining the initial system. |
| `system_size` | File specifying the Cartesian range of the system to be analyzed. |
| `spherical_grid_points_file` | File containing spherical grid points used for the spatial analysis. |
| `target_atom_index` | Atom index of the ion used as the center of the analysis. In the NaCl sample, `1` is Na+ and `2` is Cl-. |
| `rn` | Maximum radial distance from the target ion for the grid analysis, in Å. |
| `delta_d` | Radial spacing between successive layers, in Å. |
| `rc` | Radius of the local ensemble used for the collective analysis, in Å. |
| `alpha` | Gaussian weighting parameter used for the local ensemble. |
| `dip_vector_prefix` | Prefix for dipole-vector output files. |
| `frc_vector_prefix` | Prefix for force-vector output files. |
| `bck_vector_prefix` | Prefix for backward-displacement output files. |
| `fwd_vector_prefix` | Prefix for forward-displacement output files. |
| `charge_prefix` | Prefix for charge-distribution output files. |
| `file_no` | Identifier of the independent trajectory set. |
| `mdcrd` | Amber coordinate trajectory file. Multiple files may be listed and are read in the specified order. |
| `mdfrc` | Amber force trajectory file. Multiple files may be listed and are read in the specified order. |

The coordinate and force trajectory segments should be listed in corresponding order.

## System-Size File

The file specified by `system_size` defines the Cartesian range of the system to be analyzed.

The format is:

```text
X_max   Y_max   Z_max
```

The coordinate range follows the Amber box convention and is defined from 0 to the specified maximum value along each Cartesian direction.

For example:

```text
50.0   50.0   50.0
```

defines an analysis region extending from 0 to 50 Å along each of the x, y, and z axes.

---

## Spherical Grid

The spherical grid is specified by:

```text
spherical_grid_points_file  input/spherical_points.200.out
```

The `200` in `spherical_points.200.out` indicates that the file contains spherical grid points sufficient for analyses of up to **200 radial layers**.

The number of radial layers required for a calculation is determined by:

```text
rn / delta_d
```

For the supplied sample:

```text
rn       15
delta_d  0.2
```

the number of required radial layers is:

```text
15 / 0.2 = 75 layers
```

Thus, the sample calculation requires 75 radial layers, which is within the 200-layer capacity of `spherical_points.200.out`.

Users should ensure that the spherical-grid-point file contains a sufficient number of layers for the selected values of `rn` and `delta_d`.

## Temporal Resolution

The temporal resolution of the analysis is controlled by the **output interval of the MD simulation**, rather than by an internal time-interval parameter in the analysis programs.

For example, if an analysis at **100 fs** intervals is required, the coordinate (`mdcrd`) and force (`mdfrc`) files should be generated from the MD simulation at 100 fs intervals.

```text
MD simulation
     |
     | output interval = 100 fs
     v
mdcrd + mdfrc
     |
     v
cal_vector / cal_charge
     |
     v
analysis at 100 fs intervals
```

In principle, a trajectory written at a shorter time interval could be read and subsampled during post-processing. However, reading large coordinate and force trajectory files can produce substantial I/O overhead.

For this reason, the workflow used in this study prepares separate MD trajectory and force files at the time intervals required for each analysis and analyzes those files independently.

The coordinate (`mdcrd`) and force (`mdfrc`) files used together in a calculation should correspond to the same MD frames and output interval.

The trajectory and force files included in the `sample` directory are short example datasets intended only for testing the programs.

## Overall Analysis Workflow

```text
                         Independent MD trajectories
                                   |
                   +---------------+---------------+
                   |                               |
                   v                               v
              cal_vector                      cal_charge
                   |                               |
      dipole / force / displacement              charge
           for each trajectory             for each trajectory
                   |                               |
                   v                               v
          accumulate_vector                accumulate_charge
                   |                               |
                   v                               v
          merged vector data                merged charge data
                   |                               |
                   +---------------+---------------+
                                   |
                                   v
                         analyses for Figures 1–3
```

This two-stage structure was adopted because the analysis must be performed separately for multiple independent trajectories before their results are combined.

## Relation to the Manuscript

The programs in this repository support the analyses corresponding to **Figures 1–3** of:

> **Ion Hydration Generates an Extended Collective Hydration Field in Water**

The repository includes programs for calculating and accumulating:

- dipole vectors;
- force vectors;
- displacement vectors;
- solvent charge distributions;
- collective quantities derived from multiple independent trajectories.

The statistical bootstrap analysis used in the manuscript is **not performed by these programs**.

The ionic charge-scaling calculations and other additional analyses described elsewhere in the manuscript or Supporting Information are also outside the scope of this repository version unless explicitly provided.
